学习伙伴 Agent 设计方案

面向 4–6 岁儿童的全站学习伙伴：优先发现现有课程，也支持安全审核后的互动探索。

版本 0.2 · 2026-11-05 · 本文是设计提案，不代表功能已实现或通过验收。

变更目标身份隔离体验角色架构安全数据交付待决事项

0. v0.2 变更摘要

  • 新增多孩子隔离（第 2 节）：线上站点是公开 Demo，现有数据固定写入 user_id=1，且 userId 由前端请求参数传入。保存对话前必须先完成家庭账号、孩子档案和服务端身份推导。
  • 新增阶段 0：身份隔离、儿童中文 ASR 实测、限流与成本上限，都是阶段 1 的前置条件。
  • 重新设计角色：不再沿用现有 Mimi 形象。优先参考许可明确的开源素材，删除对商业 IP 的参考。
  • 阶段 1 不接大模型：课程向导只用检索，大模型和审核链路放到阶段 2。
  • 新增延迟预算；自由探索改为“预制知识卡优先，实时生成兜底”。

1. 目标与已确认需求

孩子是主要操作者，家长通常陪同。通过全站常驻入口，让孩子用语音表达学习意愿，先推荐现有课程；孩子确认后跳转。没有合适课程时，通过简短讲解、问题和点击互动开展探索。

  • 课程页面默认提供当前课程及学习项上下文，支持针对当前内容答疑。
  • 允许探索恐龙、宇宙、动物等儿童知识；内容优先来自预制知识卡，实时生成内容经自动安全和适龄审核后展示。
  • 默认语音播报，提供文字、配图和点击互动。
  • 按孩子分别保存完整文字对话和学习情况，只有本家庭家长可查看；不默认保存原始录音。
  • 大模型使用阿里云百炼，服务端持有密钥；角色为新设计的原创卡通小老鼠，活泼好奇、造型简洁。
产品原则：课程优先、孩子确认、短回合互动、审核后展示、记录有依据、数据按家庭隔离。安全审核降低风险，但不能保证零漏判。

2. 家庭账号与多孩子隔离

2.1 现状

  • app_user 只有一条记录，所有学习数据写入 user_id=1。
  • 多个 Controller 使用 @RequestParam(defaultValue = "1") Integer userId，前端 api/progress.js、api/wrongAnswer.js 固定传 userId: 1。改成多用户后，如果仍由客户端传 ID，任何人改参数就能读写别人的数据（越权）。
  • parent_game_setting 只有一条全局家长密码；ChildGrowthAccessFilter 只保护 /api/v1/child-growth/ 和 /api/v1/parent-settings/。

2.2 模型

family（家庭）1 ── n  guardian_credential（家长登录凭证）
family         1 ── n  child_profile（孩子档案：昵称、头像、出生年月）
child_profile  1 ── n  学习进度、错题、时长、agent 会话 …
  • 家长登录：建议邮箱 + 密码（不需要短信费用），密码用现有带盐摘要方案或 BCrypt；登录失败锁定沿用 failed_attempts / locked_until 思路。
  • 会话：服务端 Session，HttpOnly; Secure; SameSite=Lax Cookie；写操作需 CSRF 防护。
  • 孩子切换：登录后孩子点头像进入；当前孩子 ID 存在服务端 Session 中。家长区域（查看、删除记录、设置）需再次输入家长密码。
  • 身份推导：所有接口从 Session 取 family_id 和 child_id，不再接受客户端传入的 userId。查询一律带 family_id/child_id 条件，资源 ID 不属于当前家庭时返回 404。
  • 游客模式：未登录访客可浏览课程、试用课程向导；不保存 Agent 对话，限额更低。
  • 监护人同意：家长首次启用 Agent 前阅读说明并确认（记录内容、语音供应商、保留期限、删除方式），保存同意版本与时间；未同意时 Agent 不可用。

2.3 存量数据迁移

新 Flyway 迁移创建 family、guardian_credential、child_profile；把现有 user_id=1 的数据归入一个“默认家庭”的默认孩子。站点所有者首次登录时认领这个家庭。迁移前备份 english.db。现有业务表的 user_id 语义改为 child_id（可通过新增列或保留列名并改外键实现，实施计划中再定）。

2.4 改造范围

这项改造覆盖全站，不只是 Agent：所有带 userId 的 Controller、Service、Repository 查询、前端 API 调用和家长中心都要修改。验收重点：两个家庭、每家两个孩子的数据交叉访问测试全部拒绝。

3. 体验设计

3.1 全站入口与状态

小老鼠图标默认安静。点击展开面板，提供“说一说”和可点击的学习入口。状态包括：待机、录音中、识别中、思考中、播报中、等待选择、异常。课程页面展开时保留学习位置；关闭面板不触发课程跳转。

3.2 课程推荐

孩子表达意愿 → 识别 → 关键词 / 同义词检索课程 → 展示 1–3 个候选 → 孩子确认 → 跳转

阶段 1 用课程名、主题、学习项词表和人工维护的同义词表检索，不调用大模型。推荐卡片包含课程名、配图和开始按钮。匹配不明确时提供候选或追问；无合适课程时说明并给出几个热门主题入口。未确认前不跳转；不可用或已失效的课程应提示重新选择。

3.3 课程中答疑（阶段 2）

应用提供课程 ID、名称、类型及当前学习项的必要文字；若有多个对象而指代不明，Agent 追问。不能声称自己看到了摄像头、孩子动作或未传入的页面内容。跳转新课程时需确认，退出面板后回到原学习位置。

3.4 自由探索（阶段 2）

优先使用预制知识卡：恐龙、宇宙、动物等首批主题，每张卡含一两句讲解、一张配图和一道点选题，内容参考优秀儿童科普图书改写，按项目规则通过 Flyway 迁移交付，配图与来源记录同批提交。Agent 负责检索、排序和衔接。没有命中预制卡时才实时生成，并走完整审核链路。

交互规则：先介绍一两句，再提出一个问题；优先选择题或点选，也允许语音回答。答错时鼓励并提示，可再尝试；不确定事实时承认不知道并建议与家长一起了解。不生成长篇说教、不强迫连续学习。

3.5 延迟预算

环节目标（P90）
孩子说完 → 识别文字≤ 1.5s
课程检索 / 预制卡命中 → 开始播报≤ 1s
实时生成 + 输出审核 → 开始播报≤ 4s；超过 6s 放弃并使用预设回复

输出必须整体审核后才能展示，因此不做流式输出。等待期间小老鼠播放“思考中”动画；超过 2s 播放一句预录的安抚语音（如“让我想一想”）。

3.6 中断与异常

情况建议行为
拒绝麦克风权限 / HTTP说明原因并允许文字输入或点击选项；家长可按提示调整权限或访问 HTTPS。
识别失败提示重说，保留点击选择和文字入口。
播报被浏览器阻止展示播放按钮，孩子主动点击；保留文字。
模型或审核超时不展示未审核生成内容；使用预设安全提示，并允许继续现有课程。
达到当日次数或时长上限小老鼠说明“今天聊够啦”，引导回到课程；家长可在设置中调整。
切换页面 / 关闭停止录音和播放，取消过期请求；不把旧页面响应误显示在新页面。

4. 角色与视觉

新设计一只原创小老鼠，替换现有 Mimi 形象：简洁卡通、活泼好奇，48px 小尺寸下轮廓仍可识别。需要五个状态：待机、倾听、思考、鼓励、安全提示。

4.1 优先参考开源素材

以下是候选参考来源。许可以各仓库当前 LICENSE 为准，选用前逐项核实并记录链接、版本、许可、署名要求：

来源许可（撰写时）可参考之处注意

Google Noto Emoji图形 Apache 2.0极简扁平轮廓，适合小尺寸保留许可声明，修改需注明

做法：以 MIT / Apache 2.0 / CC0 素材为基础做衍生设计（改比例、加围巾或背包等原创识别元素），输出 SVG。状态动画用 CSS transform / keyframes 实现（眨眼、耳朵抖动、点头），符合项目“不引入动画库”和 prefers-reduced-motion 约定。

4.2 流程

收集 3 个候选 → 许可核查表 → 48px / 96px / 全尺寸测试 → 家长和孩子试看 → 定稿

定稿后需同步更新 AGENTS.md 与 docs/architecture.md 中的吉祥物描述和出现场景（现规则限定在 welcome / companion / celebrate 三个场景，常驻入口需新增）。素材与来源记录同批提交。

5. 技术架构与调用链

Vue 常驻面板 / 当前页面上下文
  → 录音（复用 useRecorder，16k WAV）→ ASR → 识别文字
  → Spring Boot Agent 编排（从 Session 取 family_id / child_id）
      → 限流与配额 → 输入检查
      → 课程检索 / 预制知识卡检索      ← 阶段 1 到此为止
      → 百炼生成结构化内容 → 格式与业务校验 → 输出审核   ← 阶段 2
      → 记录文字消息与互动结果                         ← 阶段 3
  → 前端展示 → TTS 播报 → 孩子选择或继续提问

现有代码复用评估：useRecorder.js 已输出 16k 单声道 WAV，可复用；BaiduVoiceService.synthesize() 可用于 TTS；speechToText() 目前是空实现，scorePronunciation() 使用英文模型 dev_pid=1737，都不能直接用于中文自由识别，需新实现。

5.1 编排约束

  • 服务端以受控课程查询结果作为候选；模型不能自行制造可执行 URL 或直接触发跳转。对课程 ID、状态和可访问性进行服务端校验。
  • 输出采用有限类型：课程推荐、普通回答、单题互动、安全替代提示。校验字段、长度、选项数及图片来源；格式无效时降级。
  • 设置连接和读取超时、有限重试及请求取消；审核失败或不可用时关闭生成输出，使用预设内容。AI 调用放在 service/ai/，遵循项目“超时 + 降级 + 结果校验”约定。
  • 不默认启用联网搜索或任意工具；课程、页面内容及历史消息均视为数据，不能覆盖系统规则。
  • 密钥仅服务端配置；日志不记录密钥、原始音频及完整对话正文。模型、地域与配额由部署配置确定。

5.2 限流与成本上限（阶段 0 起生效）

  • 按 IP 和按孩子分别限流（如每分钟 6 次）；游客限额更低。
  • 每个孩子每日 Agent 次数上限，家长可调整；全站每日调用总额度和费用告警，超额后只提供课程检索。
  • ASR 上传音频限制时长（如 ≤ 15s）和大小。

5.3 建议接口（草案）

接口用途
POST /api/v1/auth/register、/login、/logout家长账号注册、登录、退出。
GET/POST /api/v1/children；PUT /api/v1/children/current本家庭孩子档案列表、新增、切换当前孩子。
POST /api/v1/agent/asr上传短音频，返回识别文字；不保存音频。
POST /api/v1/agent/sessions为当前孩子创建会话，可携带当前课程与学习项标识。
POST /api/v1/agent/sessions/{id}/messages提交识别后的文字及上下文，返回审核后的结构化响应。
POST /api/v1/agent/sessions/{id}/answers提交互动选择，记录结果并返回反馈。
GET /api/v1/parent/agent-sessions[/{id}]家长查看本家庭会话摘要与详情（需家长密码校验）。
DELETE /api/v1/parent/agent-sessions/{id}家长删除会话及关联记录。

接口名称与错误码仅为设计示例，不表示已经存在。所有接口不接受客户端传入的用户或孩子 ID，统一沿用项目 {code, message, data} 响应和异常约定。

6. 安全、隐私与质量

输入与输出分别检查；输出涵盖讲解、问题、选项和图片引用。审核未通过、超时、结果不确定或格式不合法时，禁止向孩子展示未审核内容，返回固定安全提示。敏感话题可引导找家长，不作恐吓或详细危险指导。

保存完整文字对话，但每次模型请求只发送当前问题、必要的课程上下文和有限近期记录，不发送孩子昵称、出生日期等档案信息；不默认保存原始录音。音频仍需经过临时传输与处理，供应商是否留存、保留时间和用途需在选型时核对，并写入监护人同意说明，不能将“不保存录音”表述成“音频不会离开设备”。

数据按家庭隔离（第 2 节）；家长查看和删除需二次校验家长密码。收集儿童信息需遵守《儿童个人信息网络保护规定》：监护人同意、最小必要、可删除、明确保留期限。建议默认保留 180 天，到期自动删除（待确认）。

测试覆盖：跨家庭 / 跨孩子越权访问、提示注入、不适龄或危险问题、事实不确定、课程不存在、审核超时、误识别、错误选项、限流触发。人工抽样复核和家长反馈用于持续改进，不能承诺零风险。

7. 学习记录与复习

对象建议字段用途
家庭 / 家长凭证 / 孩子档案见第 2.2 节身份与隔离
监护人同意家庭 ID、同意版本、时间合规记录
会话孩子 ID、主题、来源页面、课程 ID、创建时间家长按主题查找
消息会话 ID、角色、文字、时间、审核处理状态回看完整文字对话
互动会话 ID、问题、选项、孩子答案、结果、时间展示有依据的学习过程
预制知识卡主题、讲解、图片、题目、选项、来源自由探索首选内容
复习建议孩子 ID、主题、依据、生成时间、状态后续推荐与家长查看

一次答对可能是猜测，不直接标记“已掌握”；先显示“接触过”“回答过”“建议再练习”，以后再基于多次表现制定可解释的规则。删除会话时级联删除关联消息、互动、摘要与由其派生的建议。

8. 分阶段交付与验收

阶段范围验收示例
0：前置家庭账号与孩子档案、全站去除客户端 userId、存量数据迁移、监护人同意、限流与配额；儿童中文 ASR 实测两个家庭各两个孩子交叉访问全部拒绝；存量数据完整归入默认家庭；20–30 段真实 4–6 岁童声录音对比至少两家 ASR，记录字错率和延迟，选定供应商。
1：课程向导新角色入口、语音输入、关键词 / 同义词课程检索与确认跳转；不接大模型目标设备录音可用；无匹配时不虚构课程；未确认不跳转；识别到播报满足延迟预算。
2：探索伙伴首批预制知识卡、当前页答疑、百炼生成、输入输出审核、语音播放不明确指代会追问；审核失败不泄露原文；超时走预设回复；切页停止旧音频。
3：成长记录按孩子保存对话与互动、家长查看与删除、复习建议、到期自动删除只能看到本家庭记录；删除级联生效；建议有依据；不会因一次答对直接判定掌握。

每阶段需覆盖单元与接口测试、典型儿童场景人工体验、实际浏览器 HTTPS / 录音 / 播报验证和失败降级。项目正式交付遵循后端测试 → npm ci → 前端构建 → Maven 完整打包；实际模型、审核服务和部署环境须单独联调。
